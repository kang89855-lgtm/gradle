# 토스페이먼츠 연동 가이드

> 원칙: **홈페이지가 작동한 다음에 결제를 연동한다.**
> 이 저장소는 그 순서에 맞게 준비되어 있다 — 사이트는 GitHub Pages로 자동 배포되고,
> 결제는 `toss-config.js`에 키만 넣으면 켜진다.

## 현재 상태

| 구성요소 | 상태 |
|---|---|
| 사이트 배포 | `.github/workflows/pages.yml` — 브랜치에 푸시할 때마다 자동 배포 |
| 결제 버튼 | `index.html`의 `pay()` — 키가 없으면 데모 알림, 키가 있으면 실제 토스 결제창 |
| 결제 완료/실패 페이지 | `pay-success.html` / `pay-fail.html` |
| 승인 서버 | **미구현** (아래 4단계) — 이것 전까지 결제는 "인증"까지만 진행됨 |

## 연동 순서

### 1단계 — 사이트 작동 확인 (지금)
- 배포 주소: `https://kang89855-lgtm.github.io/gradle/`
- 15문항 응답 → 결과 → 결제 버튼까지 눌러 데모 알림이 뜨면 정상.

### 2단계 — 토스페이먼츠 가입 + 테스트 키 (10분)
1. https://developers.tosspayments.com 회원가입 (개인도 가능, 테스트는 계약 불필요)
2. [내 개발정보]에서 **클라이언트 키(test_ck_...)** 확인
3. `toss-config.js`의 `window.TOSS_CLIENT_KEY = ""` 안에 붙여넣고 커밋·푸시
4. 배포된 사이트에서 결제 버튼 클릭 → 실제 토스 결제창(테스트 모드)이 열림.
   테스트 카드번호로 결제해도 돈은 빠져나가지 않는다.

### 3단계 — 결제 흐름 이해
```
[사용자] 결제 버튼 → 토스 결제창(카드 인증)
   → 성공 시: pay-success.html?paymentKey=..&orderId=..&amount=..
   → 실패 시: pay-fail.html?code=..&message=..
```
여기까지는 "인증"이다. 돈이 실제로 승인되려면 **서버에서 승인 API**를 호출해야 한다.

### 4단계 — 승인 서버 (정식 오픈 직전)
- 무료로 시작: Vercel Functions 또는 Cloudflare Workers 하나면 충분.
- 서버가 할 일 (필수 2가지):
  1. `POST https://api.tosspayments.com/v1/payments/confirm`
     에 `paymentKey, orderId, amount`를 **시크릿 키(sk_)** 로 호출해 승인.
  2. **금액 검증**: 요청된 amount가 서버가 아는 가격(4,900 또는 4,410)과 일치하는지 확인.
     (프런트 가격은 조작될 수 있으므로 서버 검증이 필수)
- 시크릿 키는 서버 환경변수에만 저장한다. 저장소·프런트에 절대 커밋 금지.
- 승인 성공 시: 주문 저장 + 정밀검사 이용권 발급 → `pay-success.html`이 서버 응답을 받아 완료 표시.

### 5단계 — 정식 계약 + 라이브 키
1. 사업자등록 (콘텐츠 판매업)
2. 토스페이먼츠 전자결제 신청·계약 (심사 수일)
3. `toss-config.js`를 **live_ck_** 키로 교체, 서버 환경변수를 live 시크릿 키로 교체
4. 전자상거래법 필수 고지 확인: 환불 규정(디지털 콘텐츠 청약철회), 사업자 정보 푸터 표기

## 할인가 무결성 (마지막 제안 10%)
- 프런트: 모달은 세션당 정확히 1회만 노출 (`S.lastShown`)
- 서버: 승인 시 amount가 4,410이면 "할인 사용" 기록을 남겨 주문당 1회만 허용
- 광고 문구 "마지막이에요"가 항상 사실이 되도록, 재방문 시 자동 재할인은 넣지 않는다 (표시광고법 리스크 방지)

## 자주 막히는 곳
- 결제창이 안 열림 → 브라우저 콘솔에서 `TossPayments` 정의 여부 확인 (SDK `<script>`가 로드됐는지), 키 오타 확인
- successUrl 404 → GitHub Pages 경로 기준이므로 `pay-success.html`이 같은 폴더에 배포됐는지 확인
- 승인 400 (amount mismatch) → 서버 검증 가격과 프런트 가격 불일치
